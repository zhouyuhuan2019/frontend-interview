AI 应用岗高频题。面试官想看你是否分得清「给模型新知识」和「改模型行为」。

## 参考答案

**RAG（Retrieval-Augmented Generation，检索增强生成）**：回答前先去外部知识库**检索**相关资料，把资料拼进提示词，再让 LLM 基于资料**生成**答案。它解决「模型不知道你的私有/实时数据」以及「胡编乱造（幻觉）」的问题。

核心区别一句话：

- **RAG 改的是「知识」**——推理时临时喂资料，不动模型参数；
- **微调（Fine-tuning）改的是「行为」**——用你的数据继续训练，把风格、格式、领域能力写进权重。

| 维度 | RAG | 微调 |
| --- | --- | --- |
| 解决的问题 | 知识时效、私有数据、可溯源 | 语气风格、输出格式、领域术语 |
| 成本 | 低，维护知识库与向量库 | 高，需标注数据与训练算力 |
| 更新速度 | 秒级，改文档即生效 | 慢，需重新训练与部署 |
| 可解释性 | 强，能给出引用来源 | 弱，说不清模型为何这样答 |
| 幻觉 | 可缓解（有据可依） | 不能根治 |
| 典型场景 | 企业知识库问答、文档助手 | 客服语气统一、特定格式生成 |

实践中二者**不互斥**：常见做法是先微调让模型「会按格式回答」，再叠加 RAG 提供「最新知识」。

## 原理讲解

RAG 分两步：**离线建库** + **在线检索生成**。

离线建库：

1. **切分（Chunking）**：把文档切成 200~800 Token 的片段，保留重叠避免语义断裂；
2. **向量化（Embedding）**：用嵌入模型把每个片段转成向量；
3. **入库**：向量 + 原文 + 元数据写入向量数据库。

在线查询：

1. 把用户问题也向量化；
2. 在向量库里做相似度检索，取 Top-K 片段；
3. 把片段连同问题拼进提示词交给 LLM 生成答案，并可附上引用。

下面用固定语料模拟一次「语义检索 → 取 Top-K」：

```js run
// 真实维度是 768/1536，这里用 3 维向量演示（已是嵌入模型输出）
const docs = [
  { text: 'Vue 的响应式基于 Proxy 拦截属性访问', vec: [0.9, 0.1, 0.2] },
  { text: 'RAG 通过检索外部知识减少幻觉', vec: [0.2, 0.9, 0.3] },
  { text: 'HTTPS 用 TLS 加密传输内容', vec: [0.1, 0.2, 0.9] },
]
const queryVec = [0.3, 0.85, 0.25] // 问题「怎么让大模型回答更准确」的向量

function cosine(a, b) {
  const dot = a.reduce((s, x, i) => s + x * b[i], 0)
  const na = Math.sqrt(a.reduce((s, x) => s + x * x, 0))
  const nb = Math.sqrt(b.reduce((s, x) => s + x * x, 0))
  return dot / (na * nb)
}

const ranked = docs
  .map((d) => ({ ...d, score: cosine(queryVec, d.vec) }))
  .sort((a, b) => b.score - a.score)

console.log('检索 Top-2：')
ranked.slice(0, 2).forEach((d, i) =>
  console.log(`${i + 1}. ${d.text}（相似度 ${d.score.toFixed(3)}）`),
)
```

```text output
检索 Top-2：
1. RAG 通过检索外部知识减少幻觉（相似度 0.992）
2. HTTPS 用 TLS 加密传输内容（相似度 0.490）
```

检索靠的是**向量语义相似**，而不是关键词命中——这正是 RAG 能召回「换个说法提问」的原因。

**常见优化**：混合检索（向量 + 关键词 BM25）、重排（Rerank 用交叉编码器精选）、查询改写（把口语问题扩写成多个检索式）、父文档/小片段策略（小块检索、大块喂给模型）。

## 追问与易错点

- **RAG 能彻底消灭幻觉吗？** 不能。检索不到、检索错、或模型不理会资料都会产生幻觉；要靠引用约束、答案兜底和评测集持续监控。
- **切块越大越好吗？** 不是。块太大噪声多、检索不准还占上下文；块太小语义不完整。需按文档结构调，并保留重叠。
- **RAG 和长上下文冲突吗？** 不冲突。长上下文是「能塞多少」，RAG 是「该塞哪些」；窗口再大，全量塞入也贵且会被稀释，检索仍必要。
- **为什么不直接微调？** 知识更新频繁时微调成本高、时效差；把知识塞进权重还容易过时，RAG 更贴合「知识」类需求。
- **相似度最高的一定最相关吗？** 不一定。向量相似只是召回手段，最终相关性可再用 Rerank 或业务规则校正。
