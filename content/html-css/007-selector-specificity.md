## 参考答案

优先级从高到低：**`!important` > 行内样式 > ID 选择器 > 类/属性/伪类选择器 > 标签/伪元素选择器 > 通配符与继承**。

常用"四元组"记法 `(a, b, c, d)`：

| 位 | 含义 | 例子 |
|---|---|---|
| a | 行内样式 | `style="..."` |
| b | ID 选择器个数 | `#nav` |
| c | 类、属性选择器、伪类个数 | `.item`、`[type]`、`:hover` |
| d | 标签、伪元素个数 | `div`、`::before` |

比较规则：**从高位到低位逐级比较**，高位胜出即结束，**不进位**（11 个类也比不过 1 个 ID）。优先级完全相同则**后声明的生效**（源码顺序覆盖）。

## 原理讲解

计算几个例子：

```css
/* (0,0,0,1)：1 个标签 */
div { color: black; }

/* (0,0,1,1)：1 个类 + 1 个标签 */
.list li { color: blue; }

/* (0,1,0,0)：1 个 ID，直接胜出 */
#title { color: red; }
```

几个容易算错的选择器：

- `*`（通配符）、`>`、`+`、`~`（组合器）**权重为 0**，不参与计数；
- `:not()`、`:is()` 本身的权重不计，但**内部参数要算**（取参数中最高者）；`:where()` 及其参数永远为 0；
- `::before`、`::after` 等伪元素算 1 个 d 位；`:hover`、`:first-child` 等伪类算 1 个 c 位。

`!important` 凌驾于所有普通声明之上，多个 `!important` 之间仍按四元组比较：

```css
.a { color: red !important; }
#b { color: blue !important; } /* (0,1,0,0) 胜 (0,0,1,0)，blue 生效 */
```

继承来的样式**没有优先级概念**（可视为最低），任何直接命中元素的选择器都能覆盖它，哪怕是权重 (0,0,0,1) 的标签选择器。

## 追问与易错点

- **`!important` 能覆盖行内样式吗？** 能。`!important` 的层级在行内样式之上；只有行内样式也写 `!important` 才能反超。
- **11 个类选择器能打过 1 个 ID 吗？** 不能。权重逐位比较、不进位，`b` 位有值就直接胜出，这是经典易错题。
- **优先级相同怎么办？** 比源码顺序，后写的生效；多个样式表则后加载的覆盖先加载的。
- **工程中如何避免优先级失控？** 少用 ID 写样式、不用 `!important`（覆盖第三方库除外）、用 BEM 等规范保持单层类选择器，让覆盖成本可预期。
- **CSS 变量参与优先级吗？** 参与。`--color` 的取值按声明它的选择器优先级和层叠规则解析，变量提升主题能力的同时也遵守同一套规则。
