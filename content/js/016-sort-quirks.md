先猜一下下面三行的输出：

```js
console.log([10, 9, 1].sort())
console.log([1, 2, 10, 20].sort())
console.log(['b', 'a', 'C'].sort())
```

## 参考答案

```text output
[1, 10, 9]
[1, 10, 2, 20]
['C', 'a', 'b']
```

- 默认排序不是按"数值大小"，而是按"**字符串大小**"——`sort()` 把所有元素转成字符串，再按 UTF-16 码元逐个比较。
- `'10'` 的首字符 `'1'` 比 `'9'` 的 `'9'` 小，所以 `10` 排到了 `9` 前面。
- 大写字母码点（`'C'` = 67）小于小写（`'a'` = 97），所以 `'C'` 排在最前。

反直觉点逐条对照：

| 表达式 | 直觉 | 实际 |
|---|---|---|
| `[10,9,1].sort()` | `[1,9,10]` | `[1,10,9]` |
| `[1,2,10,20].sort()` | `[1,2,10,20]` | `[1,10,2,20]` |
| `[100,2,3].sort()` | `[2,3,100]` | `[100,2,3]` |

## 原理讲解

`Array.prototype.sort` 不传比较函数时，会把每个元素转成字符串，再按 **UTF-16 码元序列**做字典序比较。数字 `10` 变成 `'10'`，与 `'9'` 比较时先看首字符 `'1' < '9'`，于是 `10` 排在了 `9` 前面——这正是"列表里 10 排在 2 前面"的经典 bug。

```js run
// 反直觉现场：默认按字符串比较
const nums = [10, 9, 1]
console.log('默认排序:', nums.sort().join(', '))   // 1, 10, 9

// 正确写法：显式传比较函数（数值用 a - b）
const nums2 = [10, 9, 1]
console.log('数值升序:', [...nums2].sort((a, b) => a - b).join(', ')) // 1, 9, 10

// 注意：sort 会就地修改原数组，nums 已经被改过了
console.log('原数组:', nums.join(', '))            // 1, 10, 9

// 字符串排序受大小写影响
console.log('字符串:', ['b', 'a', 'C'].sort().join(', ')) // C, a, b
```

```text output
默认排序: 1, 10, 9
数值升序: 1, 9, 10
原数组: 1, 10, 9
字符串: C, a, b
```

**实际开发中的正确写法：**

- **数字排序永远传 `(a, b) => a - b`**（升序）或 `(a, b) => b - a`（降序），不要依赖默认行为。
- **`sort` 是原地排序**，会改掉原数组。不想污染原数据就先复制：`[...arr].sort(cmp)` 或 `arr.slice().sort(cmp)`。
- 字符串排序若要忽略大小写：`arr.sort((a, b) => a.localeCompare(b))`；中文/多语言可传 locale，如 `localeCompare(b, 'zh')`。
- 对象数组按字段排：`list.sort((a, b) => a.age - b.age)`。

## 追问与易错点

- **`[1,2,3].sort()` 为什么看起来正常？** 巧合。个位数时字符串比较与数值比较结果一致，一旦出现两位数就露馅。
- **`sort` 是稳定排序吗？** ES2019 起规范要求**稳定排序**（相等元素保持原顺序）。此前 V8 对数组用不稳定排序，行为不完全一致。
- **数字全是数字、不传比较函数能得到正确结果吗？** 只有"所有数字位数相同"或"恰好字典序等于数值序"时才正确，不能依赖。
- **`sort()` 返回什么？** 返回排序后的**同一个数组引用**（原地排序），所以 `arr.sort()` 之后原数组已变。
- **比较函数返回布尔值可以吗？** 不行。规范要求返回负数/正数/0；写 `(a, b) => a > b` 时 `true` 会被当成 `1`、`false` 当成 `0`，排序结果错乱。
