## 参考答案

JSX 是 JavaScript 的语法扩展，长得像 HTML，但本质是 `React.createElement(type, props, children)`（React 17+ 自动转换为 `_jsx()`）的**语法糖**，编译产物是描述 UI 的普通 JS 对象，即虚拟 DOM 节点。

JSX 里不能直接写 `if/for` 的根本原因：`{}` 中只能放**表达式**（会产生值的式子），而 `if`、`for` 是**语句**（没有返回值）。

| 类别 | 例子 | 能否写在 `{}` 里 |
| --- | --- | --- |
| 表达式 | `a + b`、`fn()`、三元、`map()`、`&&` | 可以 |
| 语句 | `if`、`for`、`while`、`switch` | 不可以 |

常用替代写法：

```jsx
function UserList({ users, isAdmin }) {
  // 1. 提前 return，处理整体分支
  if (!users.length) return <p>暂无数据</p>

  return (
    <ul>
      {/* 2. 三元表达式做条件渲染 */}
      {isAdmin ? <button>新增</button> : null}

      {/* 3. && 做「是否显示」 */}
      {isAdmin && <button>批量删除</button>}

      {/* 4. map 做列表渲染，返回新数组，是表达式 */}
      {users.map((u) => (
        <li key={u.id}>{u.name}</li>
      ))}
    </ul>
  )
}
```

## 原理讲解

Babel 会把 JSX 编译成函数调用。下面两段代码完全等价：

```jsx
const el = <h1 className="title">Hello {name}</h1>

// 编译后（React 17+ 自动运行时）
const el = _jsx('h1', { className: 'title', children: `Hello ${name}` })
```

`{}` 里的内容最终会成为函数参数，参数位置自然只能是表达式——这就解释了为什么 `if/for` 放不进去。

一定要写复杂分支时，可以把语句挪到 JSX 之外，或者用立即执行函数（不推荐，可读性差）：

```jsx
function Badge({ level }) {
  let text
  if (level > 10) text = '资深'
  else if (level > 5) text = '熟练'
  else text = '入门'
  return <span>{text}</span>
}
```

JSX 不是模板引擎：它没有指令语法（`v-if`、`v-for`），所有逻辑都用 JS 原生能力表达，这是「Everything is JavaScript」的设计哲学。

## 追问与易错点

- **为什么列表用 `map` 而不是 `forEach`？** `forEach` 返回 `undefined`，渲染不出内容；`map` 返回新数组，React 会把数组中的元素逐个渲染。
- **`{count && <List />}` 有什么坑？** 当 `count` 为 `0` 时会把 `0` 渲染到页面上。条件值不是布尔时先转布尔：`{count > 0 && <List />}` 或 `{!!count && <List />}`。
- **为什么 React 17 之前必须 `import React`？** 因为 JSX 编译成 `React.createElement(...)`，运行时需要 `React` 变量在作用域内；17+ 的自动运行时由编译器自动注入 `_jsx` 导入，不再要求手动 import。
- **JSX 里注释怎么写？** 用 `{/* ... */}`，不能写 `//` 或 HTML 注释。
- **能直接在 JSX 里写 `switch` 吗？** 不能，它是语句。可用对象映射替代：`{ { add: <A/>, edit: <B/> }[mode] }`。
